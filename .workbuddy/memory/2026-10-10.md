### 关键决策（详见 ADR-0002）
1. **不用 Element Plus** —— 影音 UI 没有现成组件，反要覆盖它的企业后台视觉。
2. **能力跟着播放器后端走，不跟环境走**。桌面端若按 mpv 档决策会得到 MKV 地址，而 mpv 未就绪时实际在用 Web 播放器 → 浏览器放不了。这个坑差点写进去。
3. **能力单一真源** = `capabilities.json`，Rust parity 测试与前端共读。
4. 订阅式（`state` + `subscribe`）而非 111.md §53 的轮询式 getter。
5. 详情页只调无副作用的 `decide`，播放器页才调会启动 ffmpeg 的 `createSession`。

### 踩到并修掉的坑
- **parity 测试假通过**：第一版用 JSON 的 key 取 id，前端用 `id` 字段索引。注入 id 漂移后测试全绿。改用 `id` 字段 + 断言 key 必须等于 id。
  → 教训：写完测试要注入一次错误确认它会红。
- `flush()` 会重复发一条（原设计 pending 在 doSend 后仍保留）→ 改跟踪 lastSentPosition 使其幂等。
- 前端测试 DOM 未隔离：`document.body.querySelector('video')` 拿到上一个测试的元素。改为显式持有 container。
- jsdom 的 `currentTime` 只读 → prototype 上用 WeakMap 改可写。
- Vue 模板访问不了 `document` → 全屏状态要建 ref + 监听 `fullscreenchange`。

### 环境坑（下次省时间）
- 本机 **1420 端口被另一个项目（"行测刷题"）占着 IPv6 `[::1]`，vite 只绑到 IPv4** → curl 拿到别人的页面。dev 冒烟换端口，并用 `--noproxy '*'`。
- vite dev 默认绑 `[::1]`，`curl 127.0.0.1` 会 connection refused。要 curl `http://[::1]:PORT/`。
- vite dev 需要 `/api` 代理到 8080，否则请求打到 vite 自己（已加 proxy 配置）。
