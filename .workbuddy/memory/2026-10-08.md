### 项目要点
- Mosaic = AI 原生、自托管家庭影音平台。技术栈：Rust（Axum/Tokio/SQLx）+ Vue3+TS+Tauri2（六端统一）+ FFmpeg + SQLite/PostgreSQL。
- 核心抽象：MediaItem → MediaVersion → MediaFile → MediaStream；StorageProvider / MetadataProvider / HardwareProvider / ModelProvider / MediaPlayer Plugin / AI Agent+Tool+MCP。
- 首发方向：R5S / RK3588S / ARM64 + Docker。明确不做 BT/PT/下载/网盘。

### 分析结论（关键判断）
1. 文档是白皮书不是开发计划：缺字段级数据模型、API 规范、验收标准。
2. 反对按 §114 的 V0.1→V1.0 线性推进，改为垂直切片：P0 地基/Spike → P1 媒体内核 → P2 元数据 → P3 播放引擎（第一个可用版）→ P4 Web+桌面端（对外发布）→ P5 ARM/R5S → P6 移动TV → P7 AI 与生态。3 人约 48 周，1 人建议只做到 P4（约 50 周）。
3. 两个生死级 Spike 必须在 P0 出结论：S1 Tauri2 移动端原生播放器插件（Media3/ExoPlayer，PGS/ASS 字幕、Surface 叠加）；S2 RK3588 硬件转码（mainline FFmpeg 对 RKMPP 支持不完整，通常需 ffmpeg-rockchip，建议做成可切换 runtime 后端 + 自动降级链）。
4. 其他 Spike：S3 FFmpeg 进程池与资源隔离、S4 中文搜索（FTS5 无中文分词 → trigram 起步）、S5 SQLite/PG 双栈、S6 大库扫描基线。
5. 文档 8 处待修订：版本路线与 MVP 口径冲突、缺字段模型、缺 OpenAPI、缺 DoD、RK3588 应为实验特性、字幕降级策略、中文搜索方案、版本号不应写死（改 versions.lock）。

## P1 已执行（媒体内核，代码已落地，commit f35de1b）

端到端闭环已通：`mosaic-cli scan --path /media` 能把一个目录变成可查询的媒体库，
HTTP API（/libraries /media /movies /series /episodes /items/{id} /search /tasks /scan）实测可用。

**测试**：52 passed / 0 failed / 1 ignored（10k 基线）。clippy -D warnings 零警告。

**新增实现**
- `storage`：LocalStorage + 路径安全四件套（canonicalize / root boundary / symlink / permission）。
  `clean_path()` 剥掉 Windows `\\?\` 前缀——媒体路径要长期入库，不能带这个前缀。
- `media`：`naming.rs` 文件名解析器（52 条真实语料 100%）、`probe.rs` FFprobe 封装
  （超时 / 离线可测 / HDR 判定 DV 优先于 PQ）、`nfo.rs`（movie / tvshow / episodedetails）。
- `library`：入库编排。**所有 id 用确定性 UUIDv5 从自然键派生** —— 随机 id 会让每次扫描
  造出一批新作品，用户手动改的元数据和续播点全丢。
- `scanner`：遍历 + `(mtime_ns,size)` 增量指纹 + 并发（Semaphore/JoinSet）+ 可取消可暂停
  + 失败不中断。文件消失只标记 `is_available=0`，**不删除**。
- `database`：SQLx 0.9 + SQLite(WAL)。全仓库唯一允许写 SQL 的 crate。
- `migrations/0002`：索引 + FTS5 触发器 + `uq_series_title_year` 唯一约束。

**关键决定（后期别改回去）**
- 迁移用运行时 `Migrator::new(dir)`，**不用 `sqlx::migrate!`**：SQLx 0.9 已移除该宏；
  且容器里 CWD 是 /config 而迁移目录是 /usr/local/share/mosaic/migrations，编译期常量必然失效。
- 不用 `sqlx::query!` 宏（要 DATABASE_URL + .sqlx 离线缓存，跨架构 CI 上持续制造麻烦），
  改用运行时 `query()`，代价是没有编译期 SQL 校验 → 靠 repo 层集成测试补。
- 中文检索 FTS5 trigram，<3 字符降级 LIKE，FTS 异常静默降级不 500。
- 剧名提示来自所在目录名（`parse_file_in_dir`）：单看文件名分不清
  `Band.of.Brothers.S01E02.Day.of.Days` 里哪部分是剧名哪部分是集名。

**测试逼出来的真实缺陷（已修）**
1. 20 集并发入库会产生 20 条同名 series（SELECT-then-INSERT 竞态）→ 唯一索引 + ON CONFLICT DO NOTHING。
2. 正则吃掉分隔符 → `HEVC x265` 只命中第一个 → 改 `\b` 零宽边界。
3. `HDR10+` 被判成 HDR10（+ 后面不是词边界）→ HDR 关键字只在开头加词边界。
4. 年份取第一个候选会把 `1917 (2019)` 判成 1917 → 改取最后一个候选。
5. 内存 SQLite（共享缓存）并发写会报 SQLITE_LOCKED → 集成测试改用文件库（与生产 WAL 同构）。

- `metadata/tmdb.rs` / `bangumi.rs`：两个真实 Provider。Bangumi 搜到 id 后再逐个拉详情

- `metadata/merge.rs`：**`locked`（用户改过）+ `filled`（高优先级来源已填）两套集合**，
  合起来才完整表达 "NFO > 手动锁定 > Provider"。只做 locked 会被 Provider 覆盖 NFO 的值。
- `metadata/nfo.rs`：NFO 故意**不实现** `MetadataProvider`（它没有"搜索"语义），

- `metadata/images.rs`：LRU 缓存，清理优先级 still(3) > profile(4) > logo(2) > backdrop(1) > poster(0)，
  数字越大越先删。缺图占位用 **SVG 文本生成**（零依赖，不引入 image 库、不调 FFmpeg）。
- `metadata/thumbs.rs`：FFmpeg 缩略图/变体。`-ss` 必须在 `-i` **之前**（否则退化成全量解码）。
- `metadata/pipeline.rs`：队列 + 打分决策 + 落库 + 取图。`reap_running()` 回收崩溃遗留任务。
- API `/scrape`(202 异步) `/scrape/stats` `/metadata/candidates|review|cache/*`
  `/items/{id}/identify|locks|images/{kind}`；CLI `scrape|candidates|identify|lock|review|images`。
- `config`：`MetadataConfig` / `ImagesConfig`，API Key 只走环境变量（TOML 常被误提交）。
